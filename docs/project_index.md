# Project Index

A complete file-by-file map of the Libre3D repository. Generated to help orient new contributors and future Claude Code sessions — see [CLAUDE.md](../CLAUDE.md) for higher-level architecture notes.

## Root

- **`.env`** — Local environment variables, at the repo root (not `apps/editor/.env`): the dev stack's AWS settings for the API (`AWS_REGION`, the `libre3d-dev-local` `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`, `S3_BUCKET_NAME`, `PUBLISHED_SCENES_TABLE_NAME`, `USER_SCENES_TABLE_NAME`) and the public sign-in config the browser gets (`VITE_COGNITO_USER_POOL_ID`, `VITE_COGNITO_CLIENT_ID`, `VITE_COGNITO_DOMAIN`). Vite reads it with `loadEnv` for the server and `envDir` for the browser; only `VITE_` values reach the bundle.
- **`.gitignore`** — Ignores `node_modules` and `CLAUDE.md` (the latter is treated as a local/generated file, not checked in).
- **`CLAUDE.md`** — Guidance document for Claude Code instances working in this repo: commands, architecture, and conventions.
- **`README.md`** — Project overview, feature list, tech stack, setup instructions, and contribution/review workflow.
- **`package.json`** — Root workspace manifest. Defines `dev`/`build` scripts that delegate to the `editor` package via pnpm filters, and pins the `three` dependency version across the workspace via a pnpm override.
- **`pnpm-lock.yaml`** — pnpm's lockfile recording exact resolved dependency versions for the whole workspace.
- **`pnpm-workspace.yaml`** — Declares `apps/*` as the set of workspace packages, plus an `allowBuilds` entry permitting `esbuild`'s install script to run.

## `apps/editor/` — root

- **`index.html`** — The Vite HTML entry point. Loads the Tabler Icons webfont and the `<model-viewer>` custom element script from CDNs, and mounts the app at `#root` via `src/main.tsx`.
- **`package.json`** — The editor app's manifest: React 19, Three.js, `three-viewport-gizmo` (navigation gizmo), Zustand/zundo, and AWS SDK v3 clients (S3, DynamoDB, presigner) as dependencies; Vite, TypeScript, and type packages as dev dependencies. Scripts: `dev`, `build` (`tsc -b && vite build`), `preview`.
- **`package-lock.json`** — An npm lockfile present alongside the pnpm lockfile (likely stale/unused given the repo standardizes on pnpm).
- **`tsconfig.json`** — Main TypeScript config for the app source (`src/`): strict mode, ES2022 target, bundler module resolution, no emit (Vite handles bundling). References `tsconfig.node.json` as a project reference.
- **`tsconfig.node.json`** — A separate composite TypeScript project covering Node-context files (`vite.config.ts` and the server modules in `src/utils/`: `awsConfig.ts`, `awsPublishHandler.ts`, `awsSceneHandler.ts`, `publishedSceneStyle.ts`, `sceneAssets.ts`, `verifyAuth.ts`), which run under Vite's dev server rather than the browser. Its compiled output goes to `node_modules/.tmp/tsconfig.node/` so no `.js` lands beside the source.
- **`node_modules/.tmp/`** — `tsc -b` output: incremental build caches (`*.tsbuildinfo`) and the compiled `tsconfig.node.json` project; not hand-maintained.
- **`api/`** — The Vercel serverless functions, one file per route: `publish.ts` (`POST /api/publish`), `scene/[sceneId].ts` (public `GET /api/scene/:id`), `scenes/index.ts` (`GET`/`POST /api/scenes`), `scenes/[sceneId]/index.ts` (`GET`/`PUT`/`PATCH`/`DELETE /api/scenes/:id`), `scenes/[sceneId]/lock.ts` (`POST`/`DELETE /api/scenes/:id/lock`, the editing lock), `scenes/[sceneId]/assets/[action].ts` (`POST /api/scenes/:id/assets/uploads` and `…/downloads`, presigned URLs for imported assets), and `scenes/[sceneId]/thumbnail.ts` (`PUT /api/scenes/:id/thumbnail`, the gallery picture). Each is a thin adapter over a server module in `src/utils/`, which the Vite dev middleware also calls; relative imports need `.js` (Node's ES module loader on Vercel), which `tsconfig.api.json` enforces.
- **`vercel.json`** — Rewrites every client route (`/scenes`, `/edit/:sceneId`, `/try`, `/v/:sceneId`, `/auth/callback`) to `index.html`, so a hard refresh or shared link works on Vercel. A new route needs a line here.
- **`vite.config.ts`** — Vite configuration: aliases `three` to a single resolved copy (avoiding duplicate-instance issues), splits Three.js core into its own build chunk (with the chunk-size warning raised just above it), and installs `awsPublishRoutePlugin`, a dev-server middleware that serves the same routes as the Vercel functions in `api/`: `POST /api/publish` and `GET /api/scene/:id` (via `awsPublishHandler.ts`'s `handlePublishRequest` / `handlePublishedSceneRequest`) and `/api/scenes[/:id[/lock|/assets/uploads|/assets/downloads|/thumbnail]]` (via `awsSceneHandler.ts`'s `handleScenesRequest`, the same entry point the Vercel functions call).

## `apps/editor/src/` — entry & state

- **`main.tsx`** — Application bootstrap: applies the saved theme (`utils/theme.ts`), imports global styles, and renders `<App />` inside `React.StrictMode`. Deliberately imports nothing that pulls in the store or Three.js.
- **`App.tsx`** — The hand-rolled router (no router library). `/` → `LandingPage` (signed-in visitors go on to `?next` or `/scenes`), `/scenes` → `GalleryPage`, `/edit/:sceneId` → `EditorApp` (lazy-loaded), `/try` → `GuestEditorApp` (lazy-loaded, public), `/v/:sceneId` → `PublicViewer` (public), `/auth/callback` → `AuthCallback`; unknown paths redirect to `/`, and signed-out visits to a signed-in-only path redirect to `/?next=<path>`. Re-renders on navigation via `usePathname`.
- **`store/useEditorStore.ts`** — The single Zustand store for all editor state: scene entities (paths' radius and caps change through `updatePathStrokes`; the pen tool draws shapes through `addShape`, edits paths' points through `updatePath`, and moves a finished drawing's origin to its middle through `centerOrigin`, an SVG import adds its shapes and paths through `addImportedSvg`, and an image import its plane through `addImagePlane`; shapes' extrusion and bevel change through `updateShapeSolids`, the pen edits their outlines through `updateShape`, and `convertShapesToPaths` is Convert to Path), camera profiles, selection, scene/post-processing/frame settings, object states and events (`animation`) and the state each object is shown in (`viewedStates`, read through `selectViewedObjectState`; transform edits go through `updateShownTransforms`), preview mode (Play, and the transition the Edit Event panel's ▶ is playing, `previewingActionId`), and the pen tool's state (`penTool`, not saved or undoable). Wrapped in `subscribeWithSelector` + `zundo` (undo/redo; a step is recorded only when what undo restores changed) + `persist`. Since v17 `persist` keeps only editor preferences in localStorage; the scene (`selectSceneContent`) is saved per scene in the cloud and loaded with `loadScene`, which deep-merges settings over the defaults and clears undo history. v17's migration keeps only the preferences of an older blob; a scene saved there before cloud saving is dropped.

## `apps/editor/src/animation/` — state-based animation

Nothing in this folder depends on the store, React, or the DOM, so the share-link viewer can run it too.

- **`objectStates.ts`** — Object states: named looks of one object that hold only the values they change (position, rotation, scale, and a path's trim) over its own (Base State). Types (`ObjectState`, `SceneAnimation`), `resolveState` (an object's pose in a state), "State N" naming, `unwrapRotation` (gizmo rotations kept unwrapped, including the XYZ flip past 90° on Y), and the lifecycle helpers the store uses (`removeStatesOf`, `duplicateStates`). Free of Three.js too: every page loads it through the scene document. Covered by `objectStates.test.ts`.
- **`reparentStates.ts`** — `reparentStates`: keeps an object's states in place in the world when it moves to another parent (the store's reparenting, grouping, and ungrouping); values that don't depend on the parent (a trim) stay as they were. Apart from `objectStates.ts` because it needs Three.js's matrix math (`utils/entityTransforms.ts`), which only the editor may download. Covered by `objectStates.test.ts`.
- **`events.ts`** — Events: a trigger (`start`, `mouseDown`) on an object (its owner) and the transitions it runs. Types (`SceneEvent`, `EventTrigger`), `createEvent`/`createTransition` (what + adds), `normalizeEvents` (events read from a document put into shape), `transitionProblem`/`isRowValid` (a missing target or state, which Play skips and the inspector flags), and the lifecycle helpers the store uses (`removeEventsOf`, `duplicateEvents`, `getEventsUsingState`). Covered by `events.test.ts`.
- **`transitions.ts`** — The Transition action (`TransitionAction`: target, row 1, steps with duration and easing, Delay, Delay Repeat, Loop, Cycle) and its timing: `sampleTransition(action, elapsed)` says which rows a transition is between and how far, through delays, loops, and ping-pong, as Spline's player does with the same settings; `previewTiming` is what the Edit Event panel's ▶ plays. Covered by `transitions.test.ts`.
- **`easing.ts`** — The five easing curves (CSS's control points, which Spline uses too) through a small cubic-Bézier solver. Covered by `easing.test.ts`.
- **`sceneRuntime.ts`** — `SceneRuntime`: runs a scene's events from a snapshot of it. `start()` fires Start events, `click(entityId)` an object's (or its nearest ancestor's) Mouse Down events, `tick(dt)` moves time on, and `poses()` gives a pose for each object a transition has moved (its transform, and a path's trim). One transition per object; a new one on a moving object starts from where it is. Never touches the store. Covered by `sceneRuntime.test.ts`.

## `apps/editor/src/paths/` — paths (Bézier curves drawn as tubes)

Nothing in this folder depends on the store, React, or the DOM, so the share-link viewer can draw paths too.

- **`pathGeometry.ts`** — The math: path types (`PathPoint`, `PathData`, `PathStroke`), `buildPathCurve` (one cubic Bézier per pair of points, closing back to the first when closed), `pathsCenter` (the middle of the box round paths' curves, where a finished drawing's origin goes), the tube's segment count from its length, `trimToRings` / `drawRangeFor` (a trim as a range of the tube's rings, then of its index buffer), `hasCaps`, `capPose` / `createCapGeometry` (end caps placed on a ring with its own frame, so they meet the tube with no seam), and the Add menu's sample path. Covered by `pathGeometry.test.ts`.
- **`pathEditing.ts`** — The pen tool's math: the drawing plane (`nearestAxis`, `drawingPlane`, `projectOntoPlane`), the point edits (`appendPoint`, `movePoint`, `dragOutHandles`, `moveHandle` with `mirrorHandle`, `deletePoint`, `insertPoint` as a de Casteljau split, `setPointMode`), which handles show for a picked point (`visibleHandles`), and picking on screen (`nearestScreenPoint`, `nearestOnCurve`). Every edit returns a new path. Covered by `pathEditing.test.ts`.
- **`svgImport.ts`** — An SVG drawing as shapes and paths (`svgShapesToItems`, from `SVGLoader`'s shapes and their filled areas): a filled path with no stroke becomes a shape (its outlines and holes, its fill colour), each subpath of a stroked one a path (radius from `stroke-width`, closed on Z or when it ends on its start). Every segment a cubic (`curveToCubics`: lines with no handles, quadratics exactly, arcs a cubic per quarter turn, `ellipseSweep` matching `EllipseCurve`), Y up, the drawing centred and its longer side 4 units, each one's origin at its own centre, smooth where the handles line up. Covered by `svgImport.test.ts`.
- **`shapeGeometry.ts`** — Shapes: types (`ShapeRegion`, `ShapeData`, `ShapeSolid`), `buildShapeGeometry` (flat `ShapeGeometry`, or extruded and bevelled, centred on Z = 0), and the outlines as the pen tool counts them (`shapeContours`, `replaceContour`, `removeContour`, `flattenShape`). Covered by `shapeGeometry.test.ts`.
- **`ShapeMesh.ts`** — A shape's Three object; `rebuild` replaces its geometry for a new outline, extrusion or bevel.
- **`centerLine.ts`** — Convert to Path's maths (`shapeCenterLines`): the outline rasterised and thinned to a skeleton, the skeleton as a graph (spurs pruned, a crossing's two forks merged), branches paired straight through junctions and traced into strokes from their left end, recentred between the outline's edges, and fitted with cubic Béziers (corners where a stroke turns sharply); the radius is the median half-width across the strokes. `maskCenterLines` does the same from a grid. Covered by `centerLine.test.ts`.
- **`PathMesh.ts`** — A path's Three object: the tube mesh, with two cap meshes as children sharing its material (each cap its own geometry, so `setDepthPaint` can colour each where it sits). `setTrim` changes only the draw range and the caps (hidden when nothing is drawn); `rebuild` replaces the geometry for a new path or stroke; `createTrimmedGeometry` gives exports the drawn part. Covered by `PathMesh.test.ts`.

## `apps/editor/src/components/` — top-level UI

- **`EditorApp.tsx`** — The editor (the `/edit/:sceneId` page), loaded with `React.lazy` so other pages never download Three.js. `EditorApp` opens the scene (`useOpenScene`; "Opening the scene…", then "Downloading the scene's models and textures…" for imported assets this browser lacks, with Try again / Open without them if some can't be fetched, or a not-found/newer-version/error screen), then `EditorWorkspace` keeps the editing lock (`useSceneLock`; while it's held elsewhere, `ReadOnlyBanner` replaces the floating toolbar), autosaves while it holds the lock (`useSceneAutosave`, with the name and save status in the header), and wires up New Scene (creates and opens a new scene) and Sign Out, passing all of it to `EditorLayout`.
- **`EditorLayout.tsx`** — The editor itself, shared by the signed-in and guest editors: composes the sidebars and viewport, the Play preview (ended when the editor is left), the Duplicate/Reset Camera/hotkey handlers, and the export/publish flows (`utils/exportScene.ts`, `utils/publishScene.ts`). The caller supplies the header (back button, name, status), New Scene, the account for the menu (`account`, null for a guest), a banner in the floating toolbar's place, and the cloud scene Share publishes (`publishing`; null hides the Share button and tab). Also sets the dev-only `__libre3dStore` handle.
- **`GuestEditorApp.tsx`** — The editor without an account at `/try` (lazy-loaded, public). Opens the one scene kept in this browser (`utils/guestScene.ts`, default scene the first time), writes it a second after edits and on `pagehide`, and renders `EditorLayout` with a "Guest scene · Saved in this browser · Sign in" header, no Share, and no account menu. New Scene asks, then starts over. Never calls the API; imported assets stay in this browser's storage.
- **`ExportModal.tsx`** — Modal dialog with "Export Asset" (download `.glb`/`.json`) and "Share Scene" (publish to cloud, copy share link) tabs; the Share tab only when `canShare` (not for a guest). Purely presentational, driven by props/callbacks from `EditorLayout.tsx`.
- **`GalleryPage.tsx`** — The signed-in home at `/scenes`, laid out like a file browser (`SidebarLayout`): a sidebar with the account menu (theme, sign-out), a name search, and section nav; a header bar with New scene; a sort (last modified / name) and grid/list toolbar, both remembered per browser (`useStoredChoice`); and scene cards (each a link to `/edit/:sceneId` with its thumbnail, "Edited 11 hours ago", and a Published badge once published, with a Copy share link (published only)/Rename/Delete menu beside the link; deleting a published scene warns that its link stops working), or an empty state. Reads and changes scenes only through `utils/sceneLibrary.ts`.
- **`LandingPage.tsx`** — The signed-out home at `/`. Sign in hands off to Cognito's hosted login (managed login), which owns passwords, MFA setup, and resets, then returns to the `?next` path (default `/scenes`); Try it without an account opens the guest editor at `/try`. Also shown, with the reason, when `/auth/callback` fails.
- **`FloatingToolbar.tsx`** — The floating toolbar centered over the viewport: transform tool buttons (translate/rotate/scale, each of which puts the pen down), the Pen (P; disabled while view only), a local/world space toggle, and an "Add Shape" dropdown that creates new entities (cube, sphere, torus, path, directional light) or imports a file (Import...: a `.glb` model, an `.svg` whose strokes become paths, or a `.png`/`.jpg`/`.jpeg` picture on an image plane).
- **`HamburgerMenu.tsx`** — The dropdown menu triggered from the left sidebar header, exposing New Scene, Duplicate, Undo/Redo, Reset Camera, Toggle Theme, and Axis Guidelines actions with their keyboard shortcuts shown.
- **`AuthCallback.tsx`** — The `/auth/callback` page Cognito's hosted login returns to: redeems the one-time code for tokens, then replaces the URL with where the user was headed; falls back to `LandingPage` with the reason on a forged, expired, or cancelled callback.
- **`HierarchyPanel.tsx`** — Renders the scene's entity list (via an internal `HierarchyItem`) with inline rename, visibility toggle, lock toggle, delete, and click/shift-click select; filters entities by an incoming search query.
- **`ReadOnlyBanner.tsx`** — Shown over the viewport, in the floating toolbar's place, while the scene is open for editing in another tab or window: "View only" with a Take over editing button.
- **`SaveStatusIndicator.tsx`** — The line under the scene name in the editor header: Saved, Saving…, offline, View only, or what went wrong (with Retry or Reload).
- **`SceneNameField.tsx`** — The scene name in the editor header; click to rename (Enter or clicking away saves, Escape cancels).
- **`PreviewControls.tsx`** — The floating Stop chip rendered over the viewport during Play (plus an Escape binding). Play hides the whole inspector, so this is the only way back to the editor.
- **`PublicViewer.tsx`** — The read-only `/v/:sceneId` route component (the ID is a publish ID): fetches a short-lived presigned URL for the published GLB, plus the scene's background colour, from `/api/scene/:id` and displays it in a `<model-viewer>` element on that background, handling loading and error states. Also declares the `model-viewer` custom element's JSX typing.
- **`RightSidebar.tsx`** — Composes the inspector column: `InspectorTopbar`, `FramePanel`, `ViewportSettingsPanel`, `ScenePanel`, and either `StatesPanel` and `EventsPanel` (one entity selected) plus `TransformPanel`, `PathPanel` (only paths selected), `ShapePanel` (only shapes or groups selected, with shapes among them), and `MaterialsPanel` (when entities are selected) or `CameraPanel` (when none are). `StatesPanel` and `EventsPanel` sit outside the view-only fieldset, so a view-only tab can still view states and events. Also keeps which event is open in `EditEventPanel`, which then shows in place of the panels (they stay mounted, hidden) until it's closed, the selection changes, or the event is gone.
- **`ViewportCanvas.tsx`** — The core Three.js integration component: constructs `SceneManager`/`CameraManager`/`ObjectManager`, wires up the viewport hooks (renderer, controls, raycaster, Play, the pen tool), handles single- and multi-selection transform proxying (and puts the transform gizmo, moving only, on a path's picked point while its points are edited; no gizmo otherwise while the pen is on) (multi-select drags go through `updateShownTransforms` too), shows objects in their states (`applyPose`; every object in Base during Play, when the transform gizmo is detached and dropped files are ignored), imports dropped files (`.svg` as paths, `.png`/`.jpg`/`.jpeg` as an image plane, anything else as a model), syncs store state (entities, scene settings, camera profile) into the live Three.js scene each render, manages fixed-frame auto-scaling, and listens for custom "center on selected"/"orient to selected" events.
- **`ViewportOverlays.tsx`** — Small fixed UI overlaid on the viewport: the perspective/orthographic projection toggle capsule, an "Editing State 2" badge (or "Viewing" in a view-only tab; "Editing states (1/2)" for a multi-selection) while a selected object is shown in one of its states, and the pen's keys while it's drawing or editing points. (Used to also render a decorative, non-interactive 3D axis orb graphic; that's been replaced by the real navigation gizmo mounted via `viewport/hooks/useViewportGizmo.ts` — see that file's note.)

## `apps/editor/src/components/inspector/` — right-sidebar panels

- **`CameraDropdown.tsx`** — A reusable dropdown listing camera profiles, letting the user select, delete (except the default "personal" profile), or add a new one; closes on outside click.
- **`CameraPanel.tsx`** — Inspector panel (shown when nothing is selected) exposing sliders for the active camera profile's FOV (perspective only), near/far clip planes, and zoom (orthographic only).
- **`FramePanel.tsx`** — Inspector panel for the output "frame" (canvas) size: a preset selector (Responsive/1920×1080/1080×1080/Custom) plus manual width/height number inputs.
- **`InspectorTopbar.tsx`** — The sticky top bar of the right sidebar: viewport zoom display/dropdown (presets, zoom in/out, center-on/orient-to-object), and the Play/Stop, Share, and Export buttons. Play/Stop flips `isPreviewMode`; Play draws in the editor viewport itself (see `useViewportRenderer.ts` and `ViewportCanvas.tsx`), so nothing is exported.
- **`ScenePanel.tsx`** — Inspector panel for scene settings: background color (color picker + validated hex text input, with reset-to-default), the Environment Light switch and its Intensity, and Show Grid/Wireframe/Fog toggles.
- **`StatesPanel.tsx`** — Inspector panel for one selected object's states: Base State and its states; + adds one, click shows the object in it (it stays that way when deselected), double-click renames, × deletes, asking first when an event goes through the state (adding, renaming, and deleting are disabled in a view-only tab; viewing isn't).
- **`EventsPanel.tsx`** — Inspector panel for one selected object's events: one line each (trigger, target, and its rows, with a warning when something it moves is missing); click opens it in `EditEventPanel`, × deletes, + Start / + Mouse Down adds one and opens it.
- **`EditEventPanel.tsx`** — The Edit Event panel (laid out like Spline's): the trigger, then each Transition's target, its numbered state rows with a duration and easing between each pair, and its Sequence settings (Delay, Delay Repeat, Loop, Cycle); ▶ previews one transition in the viewport. Each change replaces the event's actions through `updateEvent` (number fields commit on Enter or blur, so one edit is one undo step). In a view-only tab everything shows and ▶ works; nothing else can change.
- **`ShapePanel.tsx`** — Inspector panel for the selected shapes and the shapes inside selected groups (an SVG import selects its group): Extrusion and Bevel (`updateShapeSolids`, one undo step for all, "Mixed" when they differ), and Convert to Path (`convertShapesToPaths`).
- **`DepthRamp.tsx`** — The Depth layer's ramp in `MaterialsPanel`: a colour bar with a handle per stop; click a handle to pick it, drag it to move it (one undo step), click the bar to add a stop in the colour there (up to 10).
- **`PathPanel.tsx`** — Inspector panel for the selected paths (shown when only paths are selected): Radius and Caps (the paths' own, `updatePathStrokes`), and Trim Start / Trim End as 0–100 % (stored 0–1), which go to the state each path is shown in like Transform's fields (`updateShownTransforms`), with the same marker and "Reset to Base" for one path. Several paths change together in one undo step; a value they don't share reads "Mixed". While one path's points are being edited, the picked point's position (in the path's own space) and Smooth / Corner (`updatePath`).
- **`StateValueExtra.tsx`** — The marker and "Reset to Base" shown next to a field the object's shown state sets (Transform and Path panels).
- **`TransformPanel.tsx`** — Inspector panel showing position/rotation/scale for the current selection; supports multi-selection by computing a "mixed" (blank) value per axis when selected entities disagree, and batch-updates all selected entities on change. Shows each object as it's shown (in Base or its state) and edits go there (`updateShownTransforms`); for one object in a state, the values the state sets get a marker and "Reset to Base" (`StateValueExtra`).
- **`ViewportSettingsPanel.tsx`** — Inspector panel wrapping `CameraDropdown` to select/add/delete camera profiles, auto-numbering new profiles as `camera_N`.

## `apps/editor/src/components/ui/` — generic UI primitives

The pages outside the editor (landing, gallery, status screens) are built only from these primitives (`Avatar`, `Button`, `Dialog`, `Link`, `Menu`, `NavItem`, `PageLayout`, `PageStatus`, `SearchField`, `SidebarLayout`) plus `styles/pages.css`, so a design system can replace their styling without touching page logic.

- **`Avatar.tsx`** — A round initial standing in for a person (no profile pictures).
- **`Button.tsx`** — Button primitive for the pages outside the editor, with `primary`/`secondary`/`ghost`/`danger` variants styled by `ui-button` classes in `pages.css`.
- **`Dialog.tsx`** — The app's replacement for the browser's popups: `showAlert`, `showConfirm` (optionally a `danger` confirm button) and `showPrompt` are awaitable and need no provider, so they work on any page, editor included. Each opens a native `<dialog>` (`showModal`, so focus and Escape are the browser's) in its own short-lived React root, styled by `ui-dialog` classes in `pages.css`. Don't use `window.alert`/`confirm`/`prompt`.
- **`Link.tsx`** — An `<a href>` for in-app paths: a plain left click navigates without a reload (`utils/navigation.ts`); modified clicks keep the browser's default (new tab, copy link).
- **`Menu.tsx`** — A trigger button with a dropdown of actions (`items: { label, icon?, onSelect }[]` plus an optional header line); closes on select, outside click, or Escape.
- **`NavItem.tsx`** — A sidebar navigation entry (icon + label, `aria-current` when active).
- **`PageLayout.tsx`** — Frame for the pages outside the editor: a header with the product name (linking home) and optional actions, then the page content.
- **`PageStatus.tsx`** — Full-screen spinner with a label (finishing sign-in, loading the editor).
- **`SearchField.tsx`** — Search input with a leading magnifier icon.
- **`SidebarLayout.tsx`** — File-browser frame for signed-in pages (the gallery): fixed left sidebar, header bar with title and actions, scrolling content. Stacks vertically on narrow screens.
- **`Icons.tsx`** — Hand-authored inline SVG icon components: `TranslateIcon`, `RotateIcon`, `ScaleIcon`, `PlusIcon`, `EyeIcon` (visible/hidden), `LockIcon` (locked/unlocked).
- **`PanelSection.tsx`** — A collapsible `<details>`-based section wrapper (chevron + title + body) used to group each inspector panel's contents.
- **`Select.tsx`** — A labeled `<select>` dropdown wrapper taking a list of `{label, value}` options.
- **`Slider.tsx`** — A labeled range-input slider that keeps a `--value-percent` CSS variable in sync for a gradient-fill track effect, plus a numeric value readout. A drag is one undo step (`useSliderUndoStep`).
- **`Switch.tsx`** — A labeled toggle switch (styled checkbox) component.
- **`Vector3Input.tsx`** — A labeled X/Y/Z (color-coded) numeric input row, used for position/rotation/scale editing; supports a "mixed values" blank/placeholder state for multi-selection.

## `apps/editor/src/hooks/` — app-level React hooks

- **`useHotkeys.ts`** — Global `keydown` listener implementing keyboard shortcuts (ignoring text-input focus): Ctrl/Cmd+D duplicate, Ctrl/Cmd+N new file, Ctrl/Cmd+Z/Shift+Z undo/redo (not while view only), Ctrl/Cmd+G group selection (2+ entities), Ctrl/Cmd +/- zoom, and unmodified W/E/R (transform tool, putting the pen down), P (the pen), Enter (edit the selected path's points), Delete/Backspace (remove selection), F (center/orient on selection). While the pen is on it takes Enter, Escape, Delete and Backspace first (`useViewportPenTool`). During Play only the zoom shortcuts work, so Stop finds the scene as it was.
- **`useOpenScene.ts`** — Loads `/edit/:sceneId`'s scene into the store and claims its editing lock in parallel, and reports loading/ready/not found/newer version/error. With the lock, this user's unsaved local edits are restored when the cloud copy hasn't moved on; without it, the cloud copy opens read-only (`setReadOnly`) and local edits are left alone. Also exports `fetchSceneToShow`, the same fetch-and-choose step without the store, which `useSceneLock` reuses.
- **`useSceneAutosave.ts`** — Runs a `SceneAutosaver` for each `EditSession` (a stretch of holding the editing lock; none while view only): every change to the scene's content is an edit; retakes the gallery thumbnail after saves (`ThumbnailScheduler`, at most once a minute); keeps unsaved edits in `sceneCache`, saves on leaving or losing the lock, warns before closing the tab with unsaved edits. Returns the status, `retry`, and `flush`.
- **`useSceneLock.ts`** — Keeps the open scene's editing lock (`SceneLock`) and switches the editor between editing and viewing: losing the lock makes the store read-only and reloads the view from the cloud; while viewing, the view reloads when the revision moves (camera and selection kept); getting the lock back (retry or Take over) reopens the scene, with still-current local edits, in a new edit session. Releases the lock when the scene is left, after the last save.
- **`useSliderUndoStep.ts`** — Makes a slider's drag one undo step (`ui/Slider`, the Path panel's `RangeRow`): the value updates as it drags, and history pauses after the first change until the pointer or key comes up, or the slider loses focus.
- **`useStoredChoice.ts`** — Local UI state for a choice among fixed options, remembered in this browser under a plain localStorage key (the gallery's sort and view). An unknown stored value falls back to the default.
- **`usePathname.ts`** — `useSyncExternalStore` over `window.location.pathname`; re-renders on `navigate` and Back/Forward. How `App.tsx` routes.
- **`useAuthSession.ts`** — `useSyncExternalStore` over `utils/authSession.ts`: whether someone is signed in and their email (display only). Re-renders on sign-in/out, including in another tab.
- **`useRightSidebarState.ts`** — Centralizes local (non-persisted) right-sidebar/editor-shell UI state: export/publish in-flight flags, modal open/tab state, copy-link feedback, active left-sidebar tab, search query, shape-dropdown open state, and collapsible-section states.

## `apps/editor/src/viewport/` — imperative Three.js layer

- **`CameraManager.ts`** — Owns both a `THREE.PerspectiveCamera` and `THREE.OrthographicCamera` in parallel, switches which is "active" based on projection mode, keeps both in sync with the active `CameraProfile`, and recomputes projection matrices/ortho bounds on container resize.
- **`gizmoTheme.ts`** — Builds the `three-viewport-gizmo` options object (colors, font, axis styling) for the top-right navigation gizmo by reading the app's own CSS custom properties (`styles/tokens.css`) live via `getComputedStyle`, so the WebGL-rendered gizmo stays visually in sync with the rest of the UI (including dark/light theme) instead of hard-coding a second palette. Axis colors (X/Y/Z) are carried over from the retired `.axis-orb-gizmo` placeholder for continuity. Used by `hooks/useViewportGizmo.ts`.
- **`ObjectManager.ts`** — Reconciles the store's plain-data `Entity[]` against a `Map<id, THREE.Object3D>`: creates geometries/materials per entity type (cube/sphere/torus/path/shape/image/directional light, an image as a plane the picture's shape (`utils/imagePlane.ts`), the light with an attached `DirectionalLightHelper` and light target, a path as a `PathMesh` rebuilt only when its path or stroke changes, a shape as a `ShapeMesh` rebuilt when its outline, extrusion or bevel changes), updates transforms/visuals (and a path's Base trim) in place (skipping objects mid-drag), and disposes stale objects (geometry/material/helpers) when entities are removed. Physical builds a `MeshStandardMaterial`, or a `MeshPhysicalMaterial` when its lighting layer has a clearcoat (a layer without a clearcoat value leaves an imported material's own coat alone). `applyPose` shows an object in one of its states (a path's trim included) without touching the store (`ViewportCanvas` applies it to every such object after every sync).
- **`PathEditOverlay.ts`** — What the pen tool draws over the scene (`editorOnly`, no depth test): a path's points and handles as screen-sized dots (a small shader), the lines to the handles, a thin line along the whole curve (also where a trim hides the tube), the next segment while drawing, the dot where a click would add a point, and the dot under the cursor where the pen's next click puts one (`showCursor`, in world space; larger and filled over a point a click closes or finishes the outline at). The dots and lines are in the path's own space, in a group that takes the path object's world matrix. Buffers grow by swapping in a bigger geometry (three can't grow an uploaded one).
- **`pickEntity.ts`** — `pickEntityAt`: the entity under a point of the canvas (the deepest object tagged with an entity ID that's hit first). Shared by editor clicks and Play's clicks; Play's skip hits on `editorOnly` objects such as a selection outline.
- **`thumbnailCapture.ts`** — The gallery picture: `captureViewportThumbnail` asks the render loop for one; `renderPendingThumbnail` (called by `useViewportRenderer`) renders the scene with `editorOnly` objects hidden and every object in its Base State and copies it, cropped to 16:9, into a 480×270 canvas in the same frame; encoded as JPEG, which every browser can encode (null during Play or without a viewport).
- **`InfiniteGrid.ts`** — Blender-style infinite XZ grid: a single camera-following quad (`editorOnly`) whose fragment shader draws `fwidth`-anti-aliased lines with per-pixel power-of-ten level blending, a red X / blue Z axis, and a height-scaled distance fade. Uniforms are refreshed in `onBeforeRender` from whichever camera is rendering, so perspective ↔ ortho swaps need no wiring.
- **`SceneManager.ts`** — Owns the `THREE.Scene`, an ambient light, and the `InfiniteGrid`; exposes methods to update background color, fog, light intensity, the environment light (on/off, intensity, and the map the renderer made; the ambient light is off while it's on), and grid visibility from store settings.
- **`sceneEnvironment.ts`** — `createRoomEnvironment(renderer)`: three's `RoomEnvironment` prefiltered with `PMREMGenerator`, the scene's environment light. Made once per renderer by `ViewportCanvas`.

## `apps/editor/src/viewport/hooks/`

- **`useViewportControls.ts`** — Creates and owns `OrbitControls` and `TransformControls` for the viewport: configures gizmo hitbox sizing, alt/space-modifier-driven orbit vs. pan behavior, writes live camera changes back into the active `CameraProfile` (and derived zoom %) on orbit "change" events, writes gizmo drags to the entity or to the state it's shown in (only what the tool moves, through `updateShownTransforms`), with rotations unwrapped, handles undo/redo pausing during drags (after the drag's first write, so it's one step), and subscribes to store changes (transform tool, transform space, axis-guide visibility, zoom) to keep the controls in sync.
- **`useViewportGizmo.ts`** — Creates and owns the top-right navigation gizmo (`three-viewport-gizmo`'s `ViewportGizmo`, a Blender-style clickable/draggable orientation widget): themes it via `gizmoTheme.ts`, offsets its placement to clear the fixed-width right inspector sidebar, attaches it to the shared `OrbitControls` instance, re-themes it on dark/light toggle (via a `MutationObserver` on `<html>`'s class), keeps it sized via a `ResizeObserver`, and hides/disables it during Play. Its `render()` call is threaded into `useViewportRenderer.ts`'s new `onAfterRender` hook so it draws after (not before) the main scene each frame; `ViewportCanvas.tsx` skips that call during Play, since `render()` draws even while the gizmo is disabled.
- **`useViewportPlay.ts`** — Runs events in the viewport: Play's `SceneRuntime` (built from the store on Play's first frame, Start events fired, then ticked each frame) and the Edit Event panel's ▶ preview of one transition. Each frame, before the render (`useViewportRenderer`'s `onRender`), it puts the moved objects in the runtime's poses with `ObjectManager.applyPose`, never writing the store; on Stop (or when the preview ends) they go back to their shown states. In Play it sends clicks (left button, no Alt or Space) to Mouse Down events and shows a pointer cursor over objects that have one.
- **`useViewportDepthGizmo.ts`** — Editing a Depth layer in the viewport (`depthEdit` in the store, started by `editDepth` from the layer's button or on adding one): an SVG over the canvas, redrawn each frame from 3D positions, with the axis from the origin to far, near/far cones above the axis, a dot per stop in its colour, and a radial layer's rings. The transform gizmo (translate only) moves the origin through a stand-in this hook keeps there, not the object. Dragging a handle edits the layer (`utils/depthGizmo.ts`): far turns the axis, near and stops slide along it; one undo step per drag, at most one write a frame. Only the handles take pointer events. Enter / Escape or another selection ends it; W/E/R and Delete wait meanwhile.
- **`useViewportPenTool.ts`** — The pen tool: drawing shapes (click for a corner, drag for a smooth point, on a plane facing the axis nearest the view; the second point makes a shape with `addShape`, turned so its XY plane lies on that plane, each later one is an undo step; click the first point to close, the last point / Enter / Escape to finish, which closes the outline in the last point's undo step (under 3 points, the shape goes), Backspace to take a point back; a dot under the cursor shows where the next click lands, hidden off the canvas, while the camera moves, and with Alt or Space held) and editing one path's points (`editPath`: drag points and handles, Alt-drag a handle alone, click the curve to add a point, double-click a point for smooth ↔ corner, Delete, several points picked with Shift-click or a box dragged away from them and moved, deleted or retyped together, and the transform gizmo on the last picked point through a stand-in object that `ViewportCanvas` attaches it to; Escape, Enter or a double-click away from the points ends editing). Takes its pointer events in the capture phase on the canvas's container (stopping those it uses before the camera controls and the raycaster) and its keys in the capture phase on window; pauses undo history for the rest of a gesture after its first write; drags write once a frame. Updates `PathEditOverlay` before each render (`useViewportRenderer`'s `onRender`).
- **`useViewportRaycaster.ts`** — Implements click-to-select: on pointer up (if not a drag and not a gizmo-handle click), raycasts against the live mesh map using the current active camera and dispatches `selectEntity` (supporting shift-click multi-select) based on the hit entity's `userData.entityId` (`pickEntity.ts`, shared with Play's clicks). Double-clicking a path also starts editing its points. Does nothing while the pen is on.
- **`useViewportRenderer.ts`** — Creates and owns the `THREE.WebGLRenderer` and its `requestAnimationFrame` render loop, which also draws Play: each Play frame hides the `editorOnly` objects for the render (`hideEditorOnlyObjects`, as exports and the gallery picture do), plus a `Stats` FPS overlay whose visibility is driven by the `hudOverlay` store setting. Also pins the renderer's tone mapping to `NeutralToneMapping` at exposure 1.3, matching what `<model-viewer>` applies to the published GLB so the editor shows the published tone curve rather than raw colour. Takes an optional `onAfterRender` callback, fired immediately after the main `renderer.render(scene, camera)` call each frame — used by `useViewportGizmo.ts` to draw the nav gizmo on top of (not under) the just-rendered scene. A gallery thumbnail asked for since the last frame (`thumbnailCapture.ts`) is rendered and copied just before the frame's normal render.

## `apps/editor/src/utils/` — export & publish

- **`apiFetch.ts`** — `fetch` for our own `/api/*` routes only: adds `Authorization: Bearer <access token>` (refreshing it first if needed) and raises `ApiAuthError` when signed out or the server rejects the session. Never used for presigned S3 URLs.
- **`authSession.ts`** — Browser sign-in session for Cognito managed login: authorization-code + PKCE redirect (`startSignIn`/`completeSignIn`), tokens in localStorage, `getAccessToken` with shared auto-refresh, and `signOut` (revoke + hosted logout). Deliberately not in `useEditorStore`. `sanitizeReturnTo` keeps post-sign-in paths same-site (parsed with `URL`, so `/\evil.com` is rejected).
- **`navigation.ts`** — Client-side navigation for the router: `navigate(path)` (pushState + a `libre3d-navigate` event), the location subscription behind `usePathname`, the `?next` helpers (`landingPathFor`, `getPostSignInPath`), `HOME_PATH` / `GUEST_PATH`, and `shareUrlFor(publishId)` (a published scene's `/v/` link on this deployment).
- **`sceneLibrary.ts`** — The browser side of `/api/scenes`: `listScenes`, `createScene`, `getScene` (the row includes the `assetHashes` its document uses), `saveScene` (sends this tab's session ID), `renameScene`, `deleteScene`, the lock's `claimSceneLock` (a lock held elsewhere is a `LockClaim`, not an error) and `releaseSceneLock` (optionally `keepalive`), `requestAssetUploads` / `requestAssetDownloads` (presigned URLs for imported assets), and `saveSceneThumbnail` (base64 JPEG, this tab's session); summaries carry `publishId` once published and, in the list, a presigned `thumbnailUrl`; failures raise `SceneApiError` with the status (404 gone, 409 saved elsewhere, 423 open in another session) and the rest of the error body. `listScenes` waits for saves still in flight (`settlePendingSaves`, `hasPendingSaves`). Free of the store and Three.js so the gallery can use it.
- **`editorSession.ts`** — `getEditorSessionId`: this page's random session ID, which names the editing lock's holder. A new one per tab, duplicated tab, and reload.
- **`sceneLock.ts`** — `SceneLock`: renews a held lock every 20 s, retries one held elsewhere every 10 s, checks at once when the tab is shown again, takes over on request, and releases with `keepalive` on `pagehide` unless edits are unsaved; reports each answer with the scene's revision. `releaseWhenSaved` / `cancelRelease` release after the editor leaves a scene, once its last save has landed, unless the scene is reopened first (StrictMode's remount).
- **`sceneDocument.ts`** — The saved form of a scene: `toSceneDocument` / `parseSceneDocument` with the document's own schema version (2 added the `animation` section, object states and events; 3 lets a state set a path's trim, which a v2 build would drop; 4 opens older scenes with the environment light off) and migrations. Events read from a document are put into shape (`normalizeEvents`), so a damaged one can't break the inspector or Play. New data goes in its own optional section; a document newer than the running code is refused. Covered by `sceneDocument.test.ts`.
- **`sceneThumbnails.ts`** — `ThumbnailScheduler`: after each save, retakes the gallery picture at once or, within a minute of the last one, once the minute is up (later saves fold into it); stops when an upload is refused (423/404). Capture and upload are passed in (`useSceneAutosave`).
- **`sceneAutosave.ts`** — `SceneAutosaver`: saves 2 s after the last edit (10 s at most during continuous edits), one save of a scene in flight even across autosavers, retries with backoff and on reconnect, and stops on a conflict, deletion, lost session, or lost lock. Runs `prepareSave` (the asset uploads) before each save and waits for it; a save refused for a missing asset (422) is reported and retried. Reports a `SaveStatus`, including "uploading" progress.
- **`sceneAssets.ts`** — What imported assets are called, shared by the editor and the server (no imports): an asset's ID is the SHA-256 of its bytes (`hashAsset`, `isAssetHash`), the same locally and in the cloud (`users/<sub>/assets/<hash>`); `collectAssetRefs` / `collectAssetHashes` find a scene's assets in its entities (`assetId`, image layers' `textureAssetId`); `MAX_ASSET_BYTES` (100 MB).
- **`assetTransfers.ts`** — Moves imported assets between this browser's storage and S3 with presigned URLs. `AssetUploader` (per edit session): uploads the assets a document uses that the cloud may lack, three at a time with progress (XHR). `AssetDownloader` / `downloadSceneAssets`: fetches what a scene uses that this browser lacks, checking each against its hash, one download per hash however many callers want it. `loadModelForScene` / `loadTextureForScene`: local storage, else a download for the open scene (`setSceneForAssetDownloads`); `ObjectManager` and the materials panel read through these.
- **`guestScene.ts`** — The guest editor's one scene, under the `libre3d-guest-scene` localStorage key in the scene document format (so it migrates like cloud scenes). Unreadable data starts over; a newer build's document is refused rather than overwritten; a full or blocked storage is reported (`writeGuestScene` returns false).
- **`sceneCache.ts`** — This browser's copy of unsaved scene edits, one key per scene, tagged with the user (`sub`) and base revision. Another user's entry is never loaded; `signOut` clears them all.
- **`theme.ts`** — App-wide dark/light theme: `initTheme` (called in `main.tsx`; saved choice, else follows the OS live) and `toggleTheme` (the editor menu). The theme is the `light-theme` class on `<html>`; no React state.
- **`awsConfig.ts`** — Server-side (Node) AWS setup shared by the handlers: required env vars, credentials (Vercel OIDC via `AWS_ROLE_ARN`, else the local dev key, else the SDK default chain), and the S3/DynamoDB clients. `getAwsClients(env)` makes the clients once and reuses them across requests (new ones only when the region or credentials change), with one role session shared by both and replaced early enough that every presigned URL lasts its full 15 minutes.
- **`awsPublishHandler.ts`** — Server-side (Node) publishing, shared by the Vercel functions (`api/publish.ts`, `api/scene/[sceneId].ts`) and the Vite middleware. `handlePublishRequest` (`POST /api/publish { sceneId, bgColor? }`, signed in): sets the scene's `publishId` on its own user-scenes row the first time (`if_not_exists`), writes the `published-scenes` row (`assetKey`, `ownerId`, `sourceSceneId`, `updatedAt`, and `bgColor` when it's a valid hex colour; refused if someone else owns it), and signs a PUT for `scenes/<publishId>.glb`, so nobody can publish over another user's link. `handlePublishedSceneRequest` (public `GET /api/scene/:publishId`): a 15-minute presigned GET for the GLB (older rows work too) and the row's `bgColor` (null without one). No editing lock needed.
- **`awsSceneHandler.ts`** — Server-side (Node) `/api/scenes[/:id[/lock|/assets/…]]`: `handleScenesRequest` does auth, routing, and validation for list/create/open/save/rename/delete, the editing lock, and imported assets, so the Vercel functions (`api/scenes/index.ts`, `api/scenes/[sceneId]/index.ts`, `api/scenes/[sceneId]/lock.ts`, `api/scenes/[sceneId]/assets/[action].ts`) and the Vite middleware are thin adapters. Rows in `user-scenes` keyed by the token's `sub`; documents in S3 under `users/<sub>/scenes/<sceneId>.<uuid>.json`. The lock is a 60 s lease on the row (`lockHolder` session, `lockUserId`, `lockExpiresAt`), claimed when free, already the session's, or lapsed (or always, with `takeOver`); 423 otherwise. A save writes a new object, then moves the row to it only if the session holds the lock (423 otherwise) and the revision is unchanged (409 otherwise), and renews the lease. `thumbnail` (lock holder only, renews the lease) stores a JPEG up to 256 kB at `users/<sub>/scenes/<sceneId>.thumb.jpg` and sets `thumbnailKey`; the list returns `publishId` and a presigned `thumbnailUrl`. Deleting a scene unpublishes it first (`unpublishScene`: its published-scenes row, owner only, and its GLB). Assets: `assets/uploads` (lock holder only) signs PUTs for the hashes S3 lacks, with size, type, and SHA-256 checksum as signed headers; `assets/downloads` signs GETs for hashes the row's `assetHashes` lists; a save naming an asset S3 doesn't hold intact gets 422, and records the document's assets on the row (only new ones are checked).
- **`exportScene.ts`** — Client-side scene export utilities: reads the live scene off `window.__libre3dScene`, serializes it to a `.glb` (falling back to `.gltf` on failure) via Three.js's `GLTFExporter`, and provides a generic `createDownload` helper for triggering browser file downloads (used for both asset and JSON scene-config exports). Objects tagged `userData.editorOnly` (grid, directional-light helpers, selection outlines, the multi-select proxy, the transform gizmo) are hidden for the duration of the parse so viewport furniture never lands in an exported or published GLB, and every object shown in a state is put back in Base (`showBasePoses`; `ObjectManager.applyPose` records its Base transform and a path's Base trim). `GLTFExporter` ignores draw ranges, so a path trimmed in Base is exported as only its drawn part, and one that draws nothing is left out.
- **`depthColors.ts`** — Paints a Depth layer as vertex colours: `depthRampPosition` (distance from the origin, radial or along the direction, between near and far), `sampleDepthRamp` (Spline's stop-by-stop blend, eased when smooth), `paintDepthColors` / `clearDepthColors` (keeps aside and puts back a colour attribute the geometry came with), and `syncDepthColors`, which skips a repaint with the same key. Used by `ObjectManager` and `PathMesh`; exports carry the colours as `COLOR_0`. Covered by `depthColors.test.ts`.
- **`depthGizmo.ts`** — The Depth layer gizmo's geometry in the object's space: `pointOnAxis` / `stopDistance` (where handles sit), `distanceAlongAxis` (where a ray passes the axis), and `dragFar` / `dragNear` / `dragStop` (what dragging each does). Covered by `depthGizmo.test.ts`.
- **`importImage.ts`** — `importImageFile`: a `.png`, `.jpg` or `.jpeg` dropped on the viewport or picked from Import... is stored as it is in the texture store under its SHA-256 and added as an image plane through `addImagePlane`, named after the file, blended when it has see-through pixels (checked once, scaled down past 4096 × 4096). Does nothing while view only or in Play; alerts when the picture is over `MAX_ASSET_BYTES` or can't be decoded.
- **`imagePlane.ts`** — Image planes (`type: "image"`): `imagePlaneSize` (the picture's aspect, longer side 2 units), `createImagePlaneGeometry` (a centred `PlaneGeometry` with V flipped, since stored textures load the glTF way, top row at V = 0), and `hasTransparentPixels`. Covered by `imagePlane.test.ts`.
- **`importSvg.ts`** — `importSvgFile`: an `.svg` dropped on the viewport or picked from Import... becomes shapes and paths (`paths/svgImport.ts`) through `addImportedSvg`, named after the file. Loads `SVGLoader` on first use; does nothing while view only or in Play; alerts when the SVG has nothing to import.
- **`verifyAuth.ts`** — Server-side (Node) check for `/api/*`: verifies the Bearer access token against the Cognito user pool's public keys (`aws-jwt-verify`) and returns the token's `sub` as the user ID, or a 401. The user ID never comes from the request body.
- **`sceneColor.ts`** — `getSafeColor`: normalizes a stored scene colour (which may lack the leading `#`) to a CSS/Three-safe hex. Shared by `SceneManager` (scene background, fog) and the preview surface so they can't drift on the same stored value.
- **`publishedSceneStyle.ts`** — Shared (Node + browser) validation for the styling stored with a published scene. glTF has no background colour, so the editor's `bgColor` is sent with the publish request, stored on the published-scenes row, and applied by `PublicViewer`; `normalizePublishedBgColor` accepts only strict hex colours, on the way in and on the way out, since the value is written into a style on a public page.
- **`publishScene.ts`** — Client-side publish flow: exports the live scene to a GLB blob, POSTs the scene's ID and background colour to `/api/publish` to get its publish ID and a presigned upload URL, then PUTs the blob directly to S3. The share link is `shareUrlFor(publishId)`; it stays the same when the scene is published again.
